# Luxhommè: недельная сводка по отзывам покупателей

AI-помощник, который раз в неделю забирает свежие отзывы, раскладывает их по темам и тону и присылает команде в Telegram короткую сводку: сколько отзывов по каждой теме, на что жалуются, что хвалят и что изменилось к прошлой неделе.

Данные: 48 отзывов (две недели, четыре артикула), собраны вручную в формате из задания `DATE, SKU, RATING, TEXT`. Скринкаст на 2 минуты, от загрузки отзывов до сводки в Telegram: [docs/screencast.mp4](docs/screencast.mp4).

## 1. Схема решения

![Схема](docs/architecture.png)

- **Откуда отзывы.** CSV (как в задании) или API маркетплейса. Для Wildberries есть адаптер `fetch_wildberries` (нужен токен продавца, на живом API не проверялся). Ozon и Яндекс Маркет подключаются так же: источник отдаёт список `{дата, артикул, оценка, текст}`.
- **Как попадают на разбор.** Загрузка проверяет строки (дата, оценка 1-5, текст), битые показывает в отчёте, дубли отсекает по id (хеш даты, артикула и текста). На разбор идут только отзывы без разметки.
- **Где хранится результат.** SQLite-файл: сырые отзывы, разметка (темы, тональность, флаги, версия промпта, модель), история отправок.
- **Как сводка доходит до команды.** Telegram Bot API. Запуск по расписанию описан в `.github/workflows/weekly-digest.yml` (понедельник утром); тот же запуск можно повесить на n8n или cron.

- Числа (сколько отзывов по теме, сколько жалоб, средняя оценка) считает код, а не модель. Реклама и спам в среднюю оценку не входят.
- Цитаты берутся из исходных отзывов; код проверяет, что цитата дословная (или её начало, если пришлось сократить).
- Слово «растёт» появляется только если жалоб не меньше трёх и их стало минимум на две больше.
- Отзывы, которым нельзя доверять без человека, не прячутся в статистике, а вынесены в строку «на ручную проверку».

### Запуск

Нужен Python 3.10+ без сторонних библиотек.

```bash
# без ключей: берутся записанные ответы модели из data/llm_responses
PYTHONPATH=src python -m review_digest run --provider replay --week 2026-10-05

# вживую: ключ Anthropic и бот Telegram (см. .env.example)
export ANTHROPIC_API_KEY=... TELEGRAM_BOT_TOKEN=... TELEGRAM_CHAT_ID=...
PYTHONPATH=src python -m review_digest run --week 2026-10-05 --send

# проверка качества разметки на эталоне
PYTHONPATH=src python -m review_digest eval --provider replay

# тесты
python -m unittest discover -s tests -v
```

Другие команды: `ingest`, `analyze`, `digest`, `flagged` (список отзывов на ручную проверку). Неделя уже отправлена: повторная отправка требует `--resend`.

| Путь | Назначение |
|---|---|
| `prompts/classify.md` | единственный промпт: темы, правила, формат ответа |
| `src/review_digest/analyze.py` | пачки по 15 отзывов, строгая проверка ответа модели, флаги |
| `src/review_digest/digest.py` | подсчёт, сравнение с прошлой неделей, цитаты, текст сообщения |
| `src/review_digest/llm.py` | провайдеры: `anthropic` (API), `replay` (записанные ответы), `mock` (ключевые слова, для тестов) |
| `data/` | отзывы, эталонная разметка, записанные ответы модели |
| `tests/` | 21 тест |

## 3. Как я проверял, что ИИ не ошибается в темах

1. **Закрытый список тем и строгий формат.** Код отвергает ответ с неизвестной темой, плохой тональностью, пропущенными или лишними id. Плохая пачка повторяется два раза, дальше отзывы остаются без разметки и сводка пишет, сколько не разобрано.
2. **Модель ставит только метки.** Числа и цитаты делает код, поэтому выдумать цифру или цитату нельзя. Неверную метку ловят пункты 3 и 4.
3. **Сомнительное уходит человеку.** Оценка 5 при жалобе в тексте (сарказм), низкая уверенность, отзыв «не про товар» получают флаг. В тестовых данных так пойманы «Ну просто праздник, застрял в третий раз за день, 10 из 10» и спам про чужой телеграм-канал.
4. **Эталон.** Я вручную разметил все 48 отзывов (`data/gold_labels.csv`). Команда `eval` считает точность и полноту по темам, совпадение тональности и выводит список расхождений. Её же запускает CI на записанных ответах, порог F1 0.85.
5. **Отзыв не командует моделью.** В промпте сказано, что текст отзыва это данные, а не инструкции.

Модель: Claude Sonnet 5.5, промпт из репозитория.

| Прогон | F1 по темам | Тональность | Все метки отзыва совпали |
|---|---|---|---|
| Ключевые слова без модели (нижняя планка) | 89% | 84% | 62% |
| Модель, первый промпт (записи не сохранены) | 95% | 97% | 85% |
| Модель, после правки правил промпта | 96% | 100% | 90% |

Первый прогон показал: «застревает под диваном» модель относила к удобству, а не к работе техники, добавляла «общее впечатление» к отзывам с конкретными темами, а спаму ставила разную тональность. Я уточнил эти границы в промпте и правило для спама (тональность нейтральная, то же поправил в эталоне) и прогнал заново.

Ограничения: отзывы синтетические, эталон размечал один человек (я), набор маленький. 96% на 48 отзывах не равно 96% на настоящих данных; настоящая проверка начнётся, когда маркетинг разметит 100-200 живых отзывов. Метрики сняты на Sonnet; для другой модели (например дешёвой) нужно записать ответы заново и прогнать `eval`.

## 4. Что сделал бы иначе в продакшене

- Хранил бы базу в Postgres (сейчас SQLite, и в GitHub Actions она не сохраняется между запусками) и брал бы id отзыва с маркетплейса вместо хеша текста.
- Хранил бы разметку по версиям промпта и пересчитывал прошлые недели после правок.
- Добавил бы срочный сигнал между сводками: если за сутки жалоб на артикул больше обычного, сообщение приходит сразу.
- Развёл бы темы по категориям товара: «шум» у блендера и у пылесоса значат разное.
- Дал бы в сводке ссылку на список отзывов по каждой теме.
- Считал бы расход на модель по запускам. Черновики ответов покупателям отдавал бы поддержке на ручное одобрение.

## 6. Что не проверено

- Ответы модели для демонстрации записаны заранее (`data/llm_responses/`): у меня не было ключа API. Разметку сделала модель Claude Sonnet 5.5 строго по промпту из репозитория, ответы сохранены без правок и проходят ту же проверку кодом, что и живые. Режим `replay` повторяет прогон на любом компьютере без ключей.
- Провайдер `anthropic` проверен только тестом на локальном поддельном сервере (форма запроса, заголовки, разбор ответа), на реальном API не запускался.
- Адаптер Wildberries написан по публичной документации и не проверялся на живом токене. Даты в нём берутся в UTC, на стыке недель по Москве отзыв может попасть в соседнюю неделю.
- Отправка в Telegram проверена вживую: сообщение со скринкаста реально пришло в чат.
